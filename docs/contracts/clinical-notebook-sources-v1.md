# Clinical Notebook source API snapshot

This is a consumer snapshot of Clinical Notebook's canonical `docs/api/clinical-notebook-sources-v1.openapi.json`, generated by `api.external_contract`, copied on 2026-10-08. Clinical Notebook owns this contract; update the canonical provider contract first, then refresh this snapshot.

SHA-256: `426845aa6641e9856a7ec9060d5f3bbda493c92e61287d5ad7984d63d735748f`.

Study Hub uses capability discovery, granted notebook listing, multipart file import, and import-receipt inspection from this same generic contract. Credentials require `notebooks:read` and `sources:import`; read/export grants are unnecessary. Every source carries its exact bytes and SHA-256, a stable per-lecture/material external document identity, and optional `study_hub` provenance. Source content changes require review and are never silently imported under a new external identity.

Configure the API base URL and named `cn_int_` integration token in Hub Settings → Clinical Notebook. Copy them from Clinical Notebook Connected Apps. The Hub encrypts its configuration and pins each delivery to the original installation, notebook, source revisions, and bytes. Disconnecting removes stored credentials; it does not delete remote sources or revoke the token in Clinical Notebook.

Loopback HTTP works only when the Hub and receiver run on the same computer. A Hub on another computer needs an explicitly configured HTTPS integration gateway reachable from that Hub. Existing private-host access controls still apply; the native administrative endpoint and bearer must not be exposed. Redirects are refused. Clinical Notebook must be running; no wake protocol is assumed. Offline deliveries remain pending until explicit Retry. Readiness checks never resend accepted files.

The client polls receipts briefly while a page is open and retains partial/readiness failures. The source API's `ready` receipt is its reported source readiness, not a claim of embeddings, quiz generation, or model-assisted indexing.
