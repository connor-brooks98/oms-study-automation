## Proposed v2 contract

Create `schemas/ask-v2.json` with `$id` `ask-v2.json` and the same JSON Schema draft URI.
The exact deterministic producer is a `TypeAdapter` over this union, followed by the
existing `$schema`/`$id` assignments and sorted, two-space JSON writer:

```python
TypeAdapter(
    AskRequest
    | AskThread
    | AskMessage
    | AskPageContext
    | QuizPageContext
    | GroundedClaim
    | GroundedAnswer
    | CitationView
    | AnswerEvent
).json_schema()
```

The candidate generated from the accepted isolated models (temporary only; not checked in)
was `11,276` bytes with SHA-256
`85c3c98e5fe6ab536fca28cb36c71ebd9b73e963783652ef718396177c72b195`.

Exact top-level structural contract:

```json
{
  "$id": "ask-v2.json",
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "anyOf": [
    {"$ref": "#/$defs/AskRequest"},
    {"$ref": "#/$defs/AskThread"},
    {"$ref": "#/$defs/AskMessage"},
    {"$ref": "#/$defs/AskPageContext"},
    {"$ref": "#/$defs/QuizPageContext"},
    {"$ref": "#/$defs/GroundedClaim"},
    {"$ref": "#/$defs/GroundedAnswer"},
    {"$ref": "#/$defs/CitationView"},
    {"$ref": "#/$defs/AnswerEvent"}
  ]
}
```

The generated `$defs` must have these exact public properties and required sets; field
constraints/defaults come from the accepted strict Pydantic models and are regenerated by
the adapter:

| Definition | Properties | Required |
|---|---|---|
| `AskMode` | enum `global`, `lecture`, `exam`, `quiz_pre_submit`, `quiz_post_submit` | — |
| `AskPageContext` | `kind`, `objective_ids` | `kind` |
| `QuizPageContext` | `kind`, `objective_ids`, `quiz_id`, `question_id`, `submitted`, `selected_option_id`, `correct_option_id`, `correct_answer_text`, `rationale`, `is_correct` | `quiz_id`, `question_id`, `submitted` |
| `AskRequest` | `query`, `mode`, `scope`, `page_context`, `thread_id` | `query`, `mode`, `scope` |
| `AskThread` | `thread_id`, `mode`, `scope`, `page_context` | `thread_id`, `mode`, `scope` |
| `AskMessage` | `message_id`, `thread_id`, `role`, `content` | all four |
| `GroundedClaim` | `text`, `evidence_ids` | both |
| `GroundedAnswer` | `answer_markdown`, `claims`, `citations`, `insufficient_evidence`, `safe_response_reason`, `provider_request_id`, `retrieval_run_id` | `answer_markdown`, `insufficient_evidence` |
| `CitationView` | `evidence_id`, `label` | both |
| `AnswerEvent` | `event_type`, `payload` | both |

Exact field constraints/defaults for the non-shared definitions are:

- `AskPageContext.kind` is the enum `main_hub`, `exam`, `lecture`, `quiz`; `objective_ids`
  is an array of strings defaulting to `[]`.
- `QuizPageContext.kind` is the const `quiz_question`; `objective_ids` defaults to `[]`;
  `quiz_id` and `question_id` are strings with `minLength: 1`; `submitted` is boolean;
  `selected_option_id`, `correct_option_id`, `correct_answer_text`, and `rationale` are
  nullable strings defaulting to `null`; `is_correct` is nullable boolean defaulting to
  `null`; `extra` properties are forbidden.
- `AskRequest.query` is a string with `minLength: 1`; `page_context` is an `anyOf` of
  `AskPageContext`, `QuizPageContext`, and null defaulting to null; `thread_id` is a
  nullable string with `minLength: 1` defaulting to null; `scope` references unchanged
  `RetrievalScope`.
- `AskThread.thread_id` is a string with `minLength: 1`; `page_context` has the same nullable
  union/default as `AskRequest`; `scope` references unchanged `RetrievalScope`.
- `AskMessage.message_id`, `thread_id`, and `content` are strings with `minLength: 1`;
  `role` is the enum `user`, `assistant`.
- `GroundedClaim.text` is a string with `minLength: 1`; `evidence_ids` is a non-empty array
  of strings.
- `CitationView.evidence_id` and `label` are strings with `minLength: 1`.
- `GroundedAnswer.answer_markdown` is a string with `minLength: 1`; `claims` and `citations`
  default to empty arrays; `insufficient_evidence` is boolean; `safe_response_reason`,
  `provider_request_id`, and `retrieval_run_id` are nullable strings defaulting to null.
- Every non-shared object definition has `additionalProperties: false`; the unchanged
  `AnswerEvent` retains its v1 `payload` object with `additionalProperties: true`.

The shared `RetrievalScope` and `TruthMode` definitions remain unchanged dependencies of
the request/thread definitions. The `AnswerEvent` definition and its public envelope remain
unchanged as one branch of v2. Pre-submit fail-closed behavior is represented by the strict
`QuizPageContext` fields and the accepted model validators; schema consumers must continue
to use the server-side model boundary for the mode/submission invariant.

## Why a local adapter is insufficient

A local adapter could validate Ask objects at one runtime call site, but it cannot produce
the checked-in, versioned JSON Schema consumed by browser tooling and the shared contract
test. It would leave exporter output, snapshot identity, and Sol-4's generated wire
contract out of sync, allowing browser validation and server validation to drift. The
versioned shared snapshot must therefore be produced through the Sol-0-owned exporter;
duplicating its logic inside Sol-3 would not satisfy the shared wire boundary.

## Compatibility, rollout, and rollback

This is additive versioning, not an in-place migration. v1 remains the frozen event schema;
v2 is an explicit opt-in contract with a distinct `$id`, snapshot, and proposed contract tag.
There is no database backfill or data migration.

Proposed rollout after approval: Sol-0 applies the three shared-target changes and runs the
contract/reproducibility checks; Sol-4 approves and integrates the browser consumer; Sol-0
owns the `studyhub-grounded-contracts-v2` tag/integration action; Task 3.8 then documents
the API schema selection. Rollback removes only v2 exporter output, snapshot, and consumers
from the integration candidate; `ask-v1.json` is restored/verified byte-for-byte and is
never modified by rollback.
