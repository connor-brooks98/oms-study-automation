# Task 1.3 central knowledge-repository activation

Status: HELD / unapplied. This document is a proposal to Program Sol-0, not an
applied central-file change.

## Target and reason

The exact central target is:

- `src/oms_hub/app.py`, `create_app()`, immediately after the `FastAPI` app is
  constructed and after `resolved = runtime_settings.effective_settings()`.

Task 1.3 exposes `KnowledgeRepository.initialize()` but is not permitted to
edit central startup or migration files. The repository therefore exists and
is tested in isolation, while the application currently has no startup
registration that creates its three additive source-trust tables. Program
Sol-0 must apply this registration before source-trust consumers are enabled.

The call is schema registration, not feature activation. It must not change
the existing `source_trust_v1` default or register source-trust routes. New
feature flags remain off by default outside explicit development/test
configuration. A source-trust consumer must be considered available only when
the initializer succeeds and `resolved.feature_flags` explicitly enables
`FeatureFlag.SOURCE_TRUST_V1`.

## Minimal exact patch proposal (not applied)

Apply this patch only in `src/oms_hub/app.py`; the imports belong with the
existing `oms_hub` imports and the state block belongs immediately after the
`app = FastAPI(...)` construction:

```diff
@@
 from oms_hub.config import Settings, get_settings
 from oms_hub.db import Database
 from oms_hub.document_processing.anydoc_adapter import AnydocProcessor
+from oms_hub.features import FeatureFlag

@@
+from oms_hub.knowledge.repository import KnowledgeRepository
 from oms_hub.llm.anthropic import AnthropicProvider
@@
     app = FastAPI(
         title="OMS II Study Automation Hub",
         version=__version__,
         lifespan=_app_lifespan,
         docs_url=None,
         redoc_url=None,
         openapi_url=None,
     )
+    app.state.knowledge_repository = KnowledgeRepository(database)
+    app.state.source_trust_available = False
+    try:
+        app.state.knowledge_repository.initialize()
+    except Exception:
+        logger.exception(
+            "source-trust repository initialization failed; "
+            "source trust remains disabled"
+        )
+    else:
+        app.state.source_trust_available = (
+            resolved.feature_flags.is_enabled(FeatureFlag.SOURCE_TRUST_V1)
+        )
```

The initializer is intentionally called even while the flag is off because it
only performs additive, idempotent schema registration. The availability state
remains false until the explicit flag is enabled. If initialization fails, the
exception is logged, `source_trust_available` remains false, and application
startup continues; existing routes and unrelated database migrations remain
available. Sol-0 must require both the flag and this successful availability
state at any later source-trust registration boundary.

This proposal does not change `db.py`, `migrations.py`, central ORM metadata,
the schema exporter, `schemas/knowledge-v1.json`, settings defaults, the
manifest, or CP-0001. CP-0001 remains proposed and unapplied.

## Compatibility, rollback, and downstream boundary

`KnowledgeRepository.initialize()` uses `CREATE TABLE IF NOT EXISTS` and
`CREATE INDEX IF NOT EXISTS` through the existing SQLAlchemy engine transaction
boundary. Applying the proposal is additive: it preserves every old table and
row, does not alter the central ORM schema version, and does not rewrite any
existing source-trust record. Removing the proposed import/state/call is the
rollback; the already-created additive tables may remain for a later idempotent
retry, and no data deletion or destructive rollback is authorized.

`dependent_artifact_ids()` remains the safe empty result until Task 5.2
delivers and owns the artifact-provenance schema and contract. Sol-0 must not
add artifact columns, tables, joins, or nonempty behavior under this proposal.
