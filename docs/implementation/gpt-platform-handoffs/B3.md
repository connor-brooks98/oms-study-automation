## Delivered interfaces

`study_generation/gpt_lecture.py` provides:

- Frozen `LectureSourceBinding(lecture_id, subject, exam_number, revision_id, role, snapshot, is_current, is_approved)`. Role is `slides` or `cleaned_transcript`; snapshot is the existing immutable `SourceSnapshot`.
- Frozen `LectureInputs` retains the plan's original positional fields and appends `bindings=()`, `prompt_version="gpt-lecture-v1"`, `image_required=True`, and `run_styles=()`.
- `validate_lecture_inputs(inputs)` rejects absent/mismatched roles, scope/revision ownership, stale/unapproved bindings, empty objective/source text, duplicate or blank objective ids, source/asset hash changes, missing/unusable images, missing numbered slide locators, parser blockers, and mismatched/missing PPTX styles.
- `uncovered_objectives(expected, assigned)` preserves expected objective order regardless of question count.
- `parse_lecture_sources(inputs, router, asset_root, *, renderer=None)` uses the supplied `DocumentProcessorRouter` on trusted snapshots, scopes asset directories by source id hash and source SHA, retains actual extracted images and PPTX run styles, retains full-page/full-slide rendered evidence alongside extracted images (only exact duplicate asset records are deduplicated), and checks source bytes again after parsing.
- `source_asset(inputs, source_id, asset_key)` resolves selected-slide-only evidence using both identity components and verifies bytes. Transcript and other-lecture image references are rejected.
- `source_manifest(inputs)` returns detached JSON data with canonical SHA-256, verbatim objective hashes, parser metadata, source snapshots, revisions, roles, segments/styles, sidecars and numbered assets. Source and asset paths are retained for durable loading; this is a **private artifact**, not a public response.
- `lecture_inputs_from_manifest(manifest)` verifies the digest, reconstructs snapshots, parsed documents and sidecars without reparsing, verifies files and evidence, and rejects a noncanonical/inconsistent roundtrip.

`PresentationRenderer.render` now accepts PDF directly with page locators; the existing Office conversion path retains slide locators. Optional keyword limits `max_pages` and `max_pixels` reject oversized requests before raster output. B3 supplies 500 pages and 4 million pixels per page. Existing Office callers preserve their prior optional pixel policy; PDF defaults to 4 million pixels. Output remains sanitized via the existing `persist_asset` path.
