digest/content conflicts 409; malformed normalized input/invalid selection 422;
oversized file 413. Missing optional review dependency is 503. Notes, labels,
tags and errors use Jinja escaping. File reads are capped at 10 MiB + 1 byte.

## Review and candidate behavior

`get_import(*, import_id, learner_id) -> tuple[ImportPreview, ImportReceipt]`
reconstructs the stored external envelope using original row order and provenance,
after owner validation. It avoids exposing repository internals to routes.

`stage_native_review(bank, studio, *, import_id, learner_id, subject, exam_number,
label, row_numbers=None) -> BankReviewRef` adds O-approved optional explicit
selection. `None` selects all reviewable rows only when there are at most 500;
the UI always posts an explicit checkbox selection. Invalid/duplicate/out-of-range
rows and oversized batches fail. Original positions are sorted before assigning
stable local q1..q500 IDs, so checkbox order cannot change replay identity.

`reviewable_drafts(preview, import_id)` reuses the native parser to validate
single-answer stems/choices/image references. Temporary validation placeholders
for missing answers/rationales are discarded: stored drafts retain `None` and
remain blocked by existing review checks. Only valid supplied answers receive
`PROVIDED_BY_SOURCE`. Every draft requires fresh verification, with no verified
timestamp. Unsupported/malformed structures and exact duplicate rows are excluded
and identified in the original-row view. Raw bodies remain intact in bank storage.

The adapter calls only O's accepted `create_bank_import_review`, including required
learner identity. Source IDs are the actual import UUID, segment keys `row:N`,
locators `Import row N`. Display-only original identifiers never substitute for
the bridge's exact original-row/question FK joins. Different selected-row batches
can create separate runs; unchanged same-batch replay returns the existing run.

Staging creates `awaiting_review` directly and never queues work or publishes.
The existing `PracticeReviewService` handles answer verification and bounded image
upload; existing reviewed publication is the sole path to the player. No remote
asset downloader, archive extractor or image bypass was added.

The page separates imported results/IDs from publishable questions, shows original
row/QID/attempt/unknown/held/duplicate/conflict/topic counts, preserved notes/tags,
unmatched QIDs and reviewable row selection. Candidate note/card IDs are read-only,
exact-tag based and explicitly unverified for snapshot freshness. No tag or
scheduling changes are made. The generated search contains only validated numeric
note IDs. Topic claims are shown as pending proposals.
