## Delivered contract

`GeneratedQuestion` and `GeneratedLectureQuiz` implement the plan's strict JSON
shape. `validate_generated_quiz(quiz, inputs, *, require_images)` validates source
bytes/bindings, at least three questions, complete explicit objective coverage,
unique ids and normalized stems/choices, answer bounds, nonblank per-choice
explanations, source-qualified segments, slide-only images and an associated
cited slide/page segment. Existing native quiz parsing and source-reference
validation are reused. Whole-lecture image-required output needs at least one
source image; it does not require an image for every objective.

`generate_lecture_quiz(client, request_id, model, inputs, *, cancelled,
on_lifecycle, artifact_root=None, resume=False)` returns a validated private
`GeneratedLectureQuiz`. O approved the two additive artifact/resume keywords.
It forwards the supplied lifecycle callback unchanged to the client. Its batch
request ids are `request_id:batch-0001`, etc. The final question ids deterministically
namespace the provider's original ids by the immutable batch descriptor; original
ids remain in the saved raw and completed batch records.

The prompt is a checked-in asset, hashed and privately saved before dispatch.
It requires independent source-grounded clinical vignettes, supported reasoning
levels, emphasis/style preservation, explanations tied to cited evidence, and
honest missing-objective reporting. Source instructions are untrusted data.

## Durable evidence and recovery

Artifacts live under `(artifact_root or client.work_root / "gpt-artifacts") /
sha256(request_id)`. The private directory holds the immutable plan, complete B3
manifest, prompt snapshot, batch directories and final `quiz.json`. Each batch
has an exclusive dispatch claim, bounded `raw.txt`, provider metadata, and either
`complete.json` or `invalid.json`. Metadata binds manifest/prompt/requested-model/
schema/batch hashes, request/thread/turn ids and raw/validated-quiz hashes. The
manifest preserves source paths for trusted private reload; provider source text
omits filesystem paths. Staged images are checked against original approved hashes
and removed after the call.

The exclusive plan and batch claims prevent concurrent callers from dispatching
the same run twice, including conflicting model selections. Exact completed
batches are reusable without provider calls. A prior plan permits missing,
never-dispatched batches only with explicit `resume=True`. A dispatch claim
without valid completion is ambiguous and can never be replayed by this API,
including explicit resume. Corruption, changed bindings and known-invalid output
fail closed. Invalid raw output and missing-objective ids survive recovery.

O approved full lecture evidence in each deterministic batch of at most 25
objectives because no authoritative objective-to-source mapping exists. More than
20 images or 100,000 serialized source characters blocks before dispatch with
`LectureGenerationError("context_limit")`, `.objective_ids` and `.counts`.
No passages or B3 assets are silently dropped. These application ceilings are
not evidence of model capacity. Final question count remains capped at 500.

O approved explicit `requested_model`, `actual_model: null`,
`model_evidence: "unverified"`; the transport currently provides no observed actual
model. Actual-model evidence remains a separate activation requirement.
