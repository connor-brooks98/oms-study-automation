## Exact caller contract

```python
export_reviewed_quiz(
    quiz: NativeQuiz,
    image_paths: dict[str, Path],
    provenance: dict[str, object],
    output_dir: Path,
) -> tuple[Path, Path, Path]  # JSON, ZIP, PDF
```

`quiz_export.py` takes the final authoritative reviewed quiz, not model output.
O approved this exact provenance structure:

```json
{
  "questions": {
    "q1": {
      "objective_ids": ["lo-1"],
      "source_refs": [
        {"source_id": "source-1", "segment_key": "slide-1", "locator": "Slide 1"}
      ]
    }
  },
  "image_sha256": {"image-key": "64 lowercase hex characters"}
}
```

Every native question must have source/objective evidence. Image keys must match
exactly across native references, paths and expected hashes. Images must already
be sanitized PNGs; reread bytes must match both canonical sanitizer output and
expected digest. Native serialization must preserve every question/choice id and
all content. Invalid evidence raises ValueError or OSError before output writes.

Pure native JSON remains directly importable with `parse_native_quiz`. ZIP has
`quiz.json`, `manifest.json`, and safe `media/{image-key}.png` names. Its manifest
binds every native question to its image key, all source/objective provenance,
image file hashes, format version 1, and the accepted native JSON SHA-256.
All three filenames contain that same accepted-payload hash. The containing
folder hashes the full manifest, so provenance/image changes also create a new
bundle. ZIP timestamps and PDF metadata are deterministic. Existing byte-identical
exports can be returned again; mismatched files fail rather than serving stale
bytes. All output uses `verified_atomic_write`. Existing trusted-path helpers
validate the derived root and every target before writes, rejecting symlinks and
Windows junctions instead of resolving indirection away.

PDF uses existing ReportLab/PyPDF dependencies, letter-size pages, scaled actual
images, numbered questions and choices, then separate answers/explanations and
source/objective sections. Text is markup-escaped. Matching questions retain
prompt-to-choice answers only in the answer section. Headings stay with following
content. The requested beta, greater-or-equal, right arrow and en dash survive
both extraction and rendered inspection through existing fonts. No font/dependency
installation was needed. Bundle bytes remain in memory; streaming is deferred
until actual lecture sizes require it.

O owns authenticated endpoints, private download links, authoritative review and
source/image snapshot validation, and a second freshness check after rendering.
The helper has no database, authorization or source-revision side effects. O is
wiring `/studio/runs/{run_id}/exports/{json|zip|pdf}`. No shared route changes are
included here. Completed runs must agree with accepted publication content.

## B7 correction — medical glyph fidelity and portable fonts

Correction parent: `1d1dd7f1119f03676c9ead0ab25a404885bade55`.
Implementation: `0a75b65f0335473f945ee60ead54f93b01e6e535`.
Tree: `6ebdbc466d1fdbe03a6f26e9da4b8dafa71d7c04`.

O's independent review found Helvetica/Symbol changed Na⁺, K⁺, Ca²⁺ and H₂O
into text containing boxes. The earlier beta/arrow/comparison check did not prove
superscript/subscript coverage. Five new tests first failed on the reported
corruption and on missing unsupported-character rejection.

The renderer now embeds unmodified DejaVu Sans regular/bold 2.37 from the upstream
release archive. The existing repository contains no suitable font; ReportLab's
bundled Vera lacks the required Greek, superscript-plus and subscript-two glyphs.
TTFs and complete license are in `study_generation/assets/quiz_fonts`; the README
records upstream URL, exact hashes and license whitespace normalization. No font
or package was installed. Existing Hatch package selection includes the assets,
so no pyproject edit was needed. Fonts load relative to the module, making the
same bytes available on Windows without system font discovery or network use.

Every paragraph checks its exact selected font cmap before any output writes.
Missing/nonexistent glyphs raise ValueError naming only Unicode code points.
Clinical text is not transliterated or substituted. Title, body, choices,
rationale, image caption and source/objective text use the bundled font styles.
Tests reproduce the full `Na⁺ K⁺ Ca²⁺ H₂O → α-synuclein β ≥ 2 – reassess` string
in seven or more extracted positions and assert that both font subsets are
embedded. Unsupported U+0378 in title/stem/rationale/source fails without files.
Glyph coverage is not a claim of universal complex-script layout support.

The manifest now has format_version 2 and `pdf_renderer` containing version 2
plus SHA-256 for each actual loaded TTF. These fields participate in the existing
manifest-derived folder hash. Native payload SHA and filename semantics are
unchanged. Changing renderer identity creates a distinct root and preserves old
bytes; older Helvetica exports cannot be mistaken for corrected artifacts.
