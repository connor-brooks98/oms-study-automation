## Matching and parsing behavior

Rules require an exact complete parent tag ending in `::`, qualified by validated
source/product. Exact duplicate rules are accepted. Different prefixes for one
source/product, or overlapping/reused prefixes across products/sources, are
rejected as ambiguous. No real tag prefixes are preconfigured.

Matching uses equality of `prefix + exact string QID` against stored tags. It
does not use prefix search, substring search, integer conversion, case folding,
semantic search or topic inference. Requested tags are indexed in memory before
scanning supplied notes. Duplicate identical notes/keys/tag evidence collapse;
conflicting snapshots of one note ID fail. Output sorts by source/product/QID,
numeric note ID and evidence tag. Every associated card ID remains present,
including all cloze cards. An existing note with no cards emits an empty card
tuple; unmatched keys emit no match and stay available to the caller for UI
miss reporting. Raw fields/cloze text are unchanged.

Candidate query grammar is exactly the plan's lowercase `nid:` clauses with
comma-separated positive integer IDs, joined only by case-insensitive `OR` with
spaces/tabs. Outer whitespace is trimmed; interior newlines, arbitrary fields,
parentheses, quotes, AND, implicit AND, negation and other operators fail whole.
The original input is bounded to 64 KiB UTF-8, total submitted IDs to 2,000 before
deduplication, and ID values to 1–9223372036854775807. Leading zeros are permitted
for local integer note IDs. Range checks precede conversion of potentially long
digit strings, so Python's large-integer conversion limit is never relied on.
Deduplication retains first-seen ID order. Invalid syntax fails before index reads.

Preview resolves IDs only through the supplied index's `get_note`. It uses the
existing normalized `semantic_text` display helper, and emits missing IDs with
empty text/cards. It never forwards a query to Anki. A snapshot-ID change during
preview rejects the mixed result; no retry or refresh occurs.
