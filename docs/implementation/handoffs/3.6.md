## Implemented surface

The owned repository uses the existing `Database.session()` transaction boundary and
repository-local SQLAlchemy mappings. Constructing `AskRepository` idempotently creates
only the four isolated tables needed by its focused tests; it does not register models on
the central `oms_hub.models.Base`.

- `create_thread(actor_id, mode, scope, page_context=None, thread_id=None)` stores a
  strict accepted `AskThread` with an actor owner and immutable serialized scope/context.
  Passing an already-built accepted `AskThread` is also supported.
- `append_user_message` and `append_assistant_message` require the owning actor, allocate
  a per-thread sequence through an atomic database-side counter, and return accepted
  immutable `AskMessage` values. Every append to a quiz thread must supply an explicit
  `QuizPageContext` equal to the stored context; omission and question changes fail
  closed.
- `record_retrieval_run` stores source snapshot hash, evidence IDs, source revision IDs,
  a deterministic `sha256:<64 lowercase hex>` provider reference derived from the caller
  value, prompt/schema/model versions, a required validation status code, and the expected
  evidence-link cardinality. The caller's provider text is never persisted; readback
  requires the exact derived grammar. Validation outcomes are limited to `valid`,
  `invalid`, `rejected`, `insufficient`, or `error`. `retrieval_evidence`
  is the single canonical evidence / source-revision representation; links are one-to-one
  opaque IDs and reads require the stored cardinality plus contiguous ordinals to match.
  When the thread pins a nonempty source-revision tuple, links must remain inside that
  scope. Unique evidence IDs may pair positionally to the same source revision. An empty
  thread revision tuple is a broad scope and does not itself reject bounded provenance.
  Mappings, whitespace/private prose, empty outcomes, and raw evidence text are rejected.
- Persisted `RetrievalScope` JSON must contain exactly its five canonical keys and equal
  the repository's deterministic serialization on read; unknown `raw_evidence` or other
  injected keys fail closed. Persisted page context continues through Pydantic's
  `extra="forbid"` validation.
- `get_thread(thread_id, actor_id)` returns an `AskThreadView` with deterministic message
  sequence and retrieval provenance ordering. After parent authorization it reads every
  child by `thread_id` and fails closed if a persisted child actor differs from the owner;
  missing and unauthorized IDs raise the same `KeyError`, preventing ownership disclosure.
- All thread/message/retrieval IDs are bounded opaque values matching their `String(200)`
  columns; evidence and source-revision IDs honor their `String(300)` columns, provider
  request IDs honor `String(500)`, and actor IDs honor `String(320)` without rejecting
  email-like identities. Persisted IDs and actor identities are revalidated on read.
- `list_threads(scope, actor_id)` requires both an exact scope and actor. Global/exam
  threads therefore cannot appear through an unscoped or cross-actor read.
- `delete_thread` and the explicit `delete_threads_before(actor_id, before)` retention
  surface delete owned messages, runs, and links only. Canonical source/evidence records
  are never queried or deleted; retention validates every owned thread timestamp as an
  aware UTC instant before selecting or deleting rows, and no scheduler or retention
  policy configuration was added.
