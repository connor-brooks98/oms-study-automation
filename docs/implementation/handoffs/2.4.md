## Produced interfaces

- `IndexingService.index_revision(source_revision_id: str) -> IndexResult`
- `GeminiFileSearchAdmin.upload_file(path, display_name) -> UploadedFileRef`
- `GeminiFileSearchAdmin.import_file(store_name, file_name, metadata, chunking) -> OperationRef`
- `GeminiFileSearchAdmin.wait_for_operation(operation_name) -> CompletedOperation`
- `GeminiFileSearchAdmin.delete_file(file_name) -> None`
- `IndexRepository.get_document_by_source_revision(store_id, source_revision_id)`

The service consumes only `KnowledgeService.resolve_index_input()`'s
`IndexInputView`. It validates the READY state, course authority/store scope,
canonical PPTX existence, SHA-256, and configured size before the first provider
call. Course metadata is the exact five-field CP-0002 contract. PPTX uses provider
default chunking.

Upload, import, and operation identities are committed before the next fallible
phase. A retry after import failure reuses the persisted File; a retry after poll
timeout polls the persisted operation before starting another import. A completed
document is committed READY before temporary File cleanup. Cleanup failure is a
sanitized warning and cannot undo READY. A durable `cleanup:*` marker in the
existing error-category field makes a later READY call retry cleanup without
re-uploading or re-importing; successful cleanup clears the marker.

`ProviderDocument.provider_document_id` is now nullable while a provider File or
operation exists but the imported Document identity does not. This preserves the
Task 2.3 rule that a provider Document ID is provider-owned rather than fabricating
one. The existing unique `(store_id, source_revision_id)` constraint remains the
durable pre-import identity.

plus course/exam/lecture scope. It supplies no journal article ID or normalized
Markdown artifact. Task 2.4 therefore does not invent literature identity or

optional chunking config for the later journal-owned service. If Program Sol-0
