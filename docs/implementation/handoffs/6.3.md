It inserts rows without an update/delete API and uses a unique `client_event_id` constraint to return the first durable event for duplicate submissions. Corrections must be represented by a new compensating event. The canonical captured option field is `selected_option`, matching the Task 6.3 capture list; no redundant alias is exposed.

## Sol-0 adapter proposal

Runtime capture is deliberately deferred. Program Sol-0 should add one shared adapter/wiring change after the current quiz and Ask contracts are ready:

1. `src/oms_hub/web/public_quiz_routes.py` and `src/oms_hub/web/static/public_quiz.js` — inject `MasteryRepository` from `request.app.state`, preserve the existing `grade_answer(...)` call and response body, and append only after grading succeeds. Extend the browser request compatibly with optional capture metadata, including `client_event_id`, `confidence`, `assistance_level`, `response_duration_ms`, and `attempt_timestamp`; legacy clients may omit the optional fields, but omission or invalid client identity is a fail-closed capture skip, never a server-generated replacement ID. Validate optional capture metadata after grading (or through a permissive adapter) so malformed capture metadata cannot change the existing grading response. In `public_quiz.js`, add a per-question `clientEventId` state slot; generate `crypto.randomUUID()` exactly once before the first request for that attempt, persist it before sending, and reuse it on every retry of the same submission. Map `choice_id` to canonical `selected_option`, `feedback.correct` to `correct`, client duration/timestamp to the timing fields, and explicit assistance to `assistance_level` otherwise `none`.
   Before constructing `question_answered`, resolve a verified immutable `question_version_id -> approved objective IDs -> source revision hash` chain from the central question/source repositories. Never treat the legacy public `question_id`, generated artifact identity, or an unverified source as mastery provenance. If the chain is absent/stale/unapproved, or if client identity is missing/invalid, preserve the current grading response and append no mastery event (fail closed). Wrap the entire capture path—identity validation, event construction, provenance resolution, and repository append—in a safe exception boundary: ANY capture-path failure preserves the current grading response and appends no event. Never generate a server-side replacement ID for a browser retry. If verified, map the resolved version/objectives/hash, required boolean correctness, nonempty selected option, and available difficulty; no fallback provenance is permitted.
2. `src/oms_hub/ask/service.py` / `src/oms_hub/ask/routes.py` (the Task 3 owner’s files) — append `ask_question_submitted` after Ask request validation and `ask_answer_completed` only after a grounded answer reaches its terminal `done` result. Derive one stable interaction ID from the request/message identity, then use distinct stable phase IDs `${interaction_id}:submitted` and `${interaction_id}:completed`; retries of each phase reuse its phase ID, so one interaction persists both event types without suppressing completion as a duplicate. Map `AskPageContext.objective_ids` and a verified `QuizPageContext.question_id` only when the immutable question-version/objective/source lookup succeeds; otherwise these optional fields remain absent and the interaction is not treated as a question-answer event. Leave `correct`, `selected_option`, and `difficulty` null; map server/client duration and terminal timestamp to timing fields, and the retrieval packet's verified `source_snapshot_hash` to the source hash. Use `none` unless the user explicitly selected a hint, source excerpt, explanation, or answer reveal; a post-submit free-text Ask is not an automatic penalty. Do not append a completion event for validation rejection, insufficient-evidence short-circuit, cancellation, or failed generation.
3. `src/oms_hub/app.py` and the central migration/bootstrap owned by Sol-0 — import/register the mastery model before `Database.create_schema()`/migration, construct `MasteryRepository` only after that schema path completes, and register the isolated table through the normal migration path before enabling capture. This task intentionally does not edit those shared files; the repository constructor performs no DDL.

Required Sol-0 tests: preserve the existing quiz feedback JSON and grading assertions while asserting the exact mapped `LearnerEvent`; prove omitted and invalid browser client IDs preserve grading and write no event; prove `public_quiz.js` generates one client ID and reuses it after a failed/retried request without server replacement; assert resolver/provenance, event-construction/validation, and repository failures preserve grading and write no event; assert that legacy/unverified question provenance preserves grading but writes no mastery event; retry the same browser `client_event_id` and assert one persisted event; exercise Ask validation/provider failure boundaries; assert one interaction persists both `${interaction_id}:submitted` and `${interaction_id}:completed` exactly once under phase-specific retries; and run the existing quiz/Ask route suites with capture disabled to prove compatibility.
