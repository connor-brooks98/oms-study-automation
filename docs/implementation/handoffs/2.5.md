## Durable behavior

Each `run_once()` creates a unique, bounded claim token, atomically claims at most
one `IndexJob`, and fences every job write and lease release with that exact token.
A stale worker cannot overwrite or release a newer reclaimed lease, including on
the READY success path. The default lease covers five configured provider request
deadlines, the configured operation deadline, and a small buffer; an explicitly
configured lease remains authoritative.

Recovery first releases expired leases through the shared primitive, then must win
a specific per-job claim before inspecting or normalizing that job. If a live worker
wins the race, recovery makes no job or document write. `ProviderDocument` is the
crash-safe source of provider File, operation, and imported Document identities:

| Persisted state | Recovery/run action |
| --- | --- |
| `uploading_file` without File identity | eligible `run_once()` restarts upload |
| `file_uploaded` | eligible `run_once()` starts/resumes import |
| `importing` with persisted operation | operation identity is restored to the job; `run_once()` polls it |
| `importing` without operation | job and document explicitly transition to `file_uploaded` |
| `deleting` | imported Document identity is restored; `run_once()` retries the existing admin delete |
| expired lease | reclaimed, then recovery must obtain a new fenced claim |
| live lease | left untouched |
| future retry schedule | preserved unless the retry budget is already exhausted |
| exhausted retry budget | immediately becomes `terminal_failure` |

`IMPORTING -> FILE_UPLOADED` is now an explicit owned lifecycle transition and is
validated before both job and document recovery writes.

Retry policy reuses `IngestionWorker.max_attempts == 3`. Authentication, contract,
and file-too-large failures are terminal. Normalized quota/429, transient/5xx, and
timeout failures use deterministic `5 * 2**attempt` backoff and terminalize at the
budget. Returned `IndexResult` failures preserve the category and provider
identities already committed by `IndexingService`. Arbitrary exception text is
never persisted: diagnostics store only bounded categories or exception type names.
