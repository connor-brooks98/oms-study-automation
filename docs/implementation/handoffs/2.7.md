## Produced contracts

`GeminiFileSearchAdmin.snapshot_documents(store)` is the pure provider observation
boundary. It performs no indexing-repository write. A remote document is matchable
only when there is exactly one bounded `source_revision_id`, `input_key`,
`input_kind`, and lowercase `input_sha256`; conflicting duplicates are invalid
rather than first-match selected. Reconciliation uses the exact provider-store,
source-revision, and input-key tuple, preserving Task 2.6 multimodal identities.

`IndexReconciler.reconcile_store(store_id, apply=False)` returns deterministic
findings for invalid or duplicate remote identities, local/remote orphans,
identity mismatch, stale sources, and missing provider stores. The default is
read-only. `apply=True` performs only the CP-0003 repair matrix:

- a READY local input missing remotely receives the exact atomic
  `READY -> NOT_INDEXED` document/job reset while scope/input identities remain;
- a READY input for a stale/retired source schedules permanent all-input deletion;
- remote-only, duplicate, invalid, identity-mismatch, and missing-store findings
  remain report-only.

`rebuild_revision`, `delete_revision`, and `revision_status` accept a revision ID
only after the existing read-only `KnowledgeService.get_scope_sources` boundary
confirms exactly one current provider store for the canonical course/exam scope.
Wrong-scope, zero-match, and ambiguous accepted scopes fail closed. No historical
generation is silently selected.

`IndexJob` operation intent and lease token drive all-input delete/rebuild. The
worker renews before every provider mutation and token/expiry-fences every job and
provider-document write, including normal indexing, cleanup, recovery, and
terminalization. Delete runs in `input_key` order, resumes remaining inputs after
partial failure, and becomes terminal only when every input is deleted. Rebuild
retains its intent through deletion, then atomically clears provider identities,
retry/error fields, and metadata before returning every input and the job to
`NOT_INDEXED` for normal Task 2.6 reconstruction.

`build_indexing_router(container)` produces the unregistered routes:

```text
GET    /api/v1/indexing/health
GET    /api/v1/indexing/revisions/{revision_id}
POST   /api/v1/indexing/revisions/{revision_id}/rebuild
POST   /api/v1/indexing/stores/{store_id}/reconcile
DELETE /api/v1/indexing/revisions/{revision_id}
```

Health is offline and serializes only the CP-0003 allowlist. Usage aggregates
durable per-input bytes. Index/query tokens and estimated cost remain `None`; no
token, query-event, pricing, secret, path, provider metadata, provider identity,
or raw-error value is invented or exposed. `last_contract_smoke` remains `None`
because Task 2.8 live smoke work was not started.
