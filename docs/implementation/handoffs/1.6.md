## Hard transactional gate

- Two independent `Database` instances and SQLite connections race distinct
  replacements behind a deterministic barrier. Final state contains exactly
  one READY `legacy_slides` revision for the family/scope.
- The predecessor slide becomes STALE before the replacement's READY update.
- READY transcript and handout revisions in the same scope remain READY and
  indexable.
- Failure rolls back new source/revision/evidence writes and leaves the
  predecessor READY. Empty concurrent replacements are both rejected.
- The invariant therefore passed without DDL. If a future supported database
  cannot provide the same transactional proof, implementation must stop for a
  Sol-0-owned additive uniqueness schema; weakening the invariant is forbidden.
