## Implementation

`KnowledgeRepository` uses `Database.engine.begin()` for every write and does
not extend SQLAlchemy's central ORM metadata. `initialize()` is additive and
idempotent:

- `knowledge_sources.id` is the logical source ID and stores its authority.
- `source_revisions.id` stores the canonical `source_revision_id`; its
  `source_document_id` references `knowledge_sources.id`, and
  `(source_document_id, file_sha256)` is unique.
- `evidence_units.id` stores `evidence_id`; `source_revision_id` references
  `source_revisions.id`.
- Evidence scope and locator indexes are exactly
  `(course_id, exam_id, lecture_id, authority_class)` and
  `(source_revision_id, locator_kind, locator_value)`.

`create_source()` and `create_revision()` accept the domain objects as well as
the task's keyword forms. Duplicate logical sources return the matching source
and reject authority changes. Duplicate source/hash revisions return the first
stored revision without changing its state. Missing source dependencies raise
`KeyError` before any revision write.

`put_evidence_units()` resolves authority through the revision and source,
requires every unit to belong to the requested revision, and compares
`content_sha256` to `sha256_text(normalized_text)`. All validation occurs before
inserts, so a late invalid unit cannot leave earlier units persisted. Exact
retries are idempotent; changed content under an existing evidence ID is
rejected. `list_evidence()` returns all audit rows in stable `created_at, id`
order. `retire_revision()` marks the revision retired and stamps previously
unstamped evidence retirement times, preserving the records for audit.

`dependent_artifact_ids()` returns `()` because no artifact-provenance table or
shared schema is available in Task 1.3. Task 5.2 owns that future contract; no
columns or tables were invented and no HELD proposal is required for this safe
empty behavior.
