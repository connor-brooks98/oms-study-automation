## Risks and follow-up

- Known limitation: intent recognition is a deliberately bounded phrase/token classifier;
  unknown paraphrases return a benign/other category and need later rule additions rather
  than a model call.
- Known limitation: leakage detection only matches supplied protected values and explicit
  variants/abbreviations; it does not infer medical synonyms or use edit distance.
- Known limitation: punctuation-separated single-letter abbreviations are supported, while
  whitespace-separated letters remain separate tokens to preserve boundaries.
- Fix Round 1 decision: generic test-taking strategy language is a benign `concept_hint`,
  while question-scoped option elimination remains protected. Fix Round 2 tightened this to
  explicit general test-taking framing and restores all direct-answer/option-elimination
  precedence in mixed phrasing.
- Fix Round 2 decision: any normalized decimal token is an option label, including multi-digit
  values; exact token matching keeps `1` distinct from `12`. Malformed non-Sequence outer
  protected-answer values return generic no-match results, while non-string values inside a
  valid sequence remain ignored. The approved controller ruling keeps policy refusal at
  `insufficient_evidence=False`.
- Fix Round 3 decision: generic strategy classification requires explicit instructional
  framing (`How do I`, `How can I`, or `What strateg[y|ies]`) plus general test/exam context.
  Direct-answer and option-elimination checks therefore precede the benign exception; the
  broad `rule out` shortcut was removed and ambiguous language errs toward protection.
- Fix Round 4 decision: the generic strategy predicate rejects an immediately labeled
  `answer`, `choice`, `choices`, `option`, or `options` token via the existing normalized
  `_is_option_label()` helper. This preserves unlabeled instructional test-taking requests
  while protecting ASCII/fullwidth letter and multi-digit decimal labels without a second
  label parser.
- Final-review decision: direct-answer detection takes unconditional precedence within a
  generic strategy query. The removed `rule out` exception was the only mixed-clause bypass;
  unlabeled generic strategy requests remain benign.
- Fresh correction decision: bare option labels are protected only when immediately preceded
  by an explicit elimination phrase and followed by an option-list or boundary continuation.
  This closes the ASCII/fullwidth bare-label bypass without broad single-letter matches.
- Fresh option-list decision: the same helper walks adjacent labels and valid `and`/`or` joins
  before accepting a boundary continuation, so comma/ampersand/slash lists are protected while
  ordinary words following a single-letter token remain benign.
- Contract proposals: none. The Task 3.1 Ask v2 proposal remains a separate, pending Sol-0
  shared integration item; this task made no schema change.
- Next unblocked tasks: no downstream service wiring is claimed here; Task 3.7 owns later
  integration at the service boundary. Task 3.2, 3.4, and 3.6 remain governed by the
