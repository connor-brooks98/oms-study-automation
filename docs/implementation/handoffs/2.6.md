## Produced contracts

`build_index_manifest(view: IndexInputView) -> IndexManifest` consumes only the
knowledge-owned opaque view. It creates immutable `IndexManifestInput` entries
with `input_key`, `input_kind`, verified local path, media type, SHA-256, and the
direct evidence IDs belonging to that input. `IndexManifest` retains the exact
source revision, course authority, inputs, and `EvidenceRef` values.

The durable provider input keys are:

| Input | Key | Kind | Evidence scope |
| --- | --- | --- | --- |
| Task 2.5 compatibility source | `pptx` | `pptx` | all revision evidence |
| canonical PDF | `pdf` | `pdf` | all revision evidence |
| normalized Markdown | `normalized_markdown` | `markdown` | all revision evidence |
| selected image | `image.<input_sha256>` | `image` | direct asset `evidence_ids` only |

Hash-derived image keys are bounded by the accepted `ProviderDocument` grammar.
Duplicate selected assets with identical bytes share one provider input and
union only their direct evidence IDs. No legacy source ID is decoded, no
ingestion/catalog repository is imported or queried, and no literature identity
is introduced.

`ProviderCitation` represents the provider payload. `CitationCandidate` records
the selected `EvidenceRef`, match kind, and confidence.
`map_provider_citation(...) -> EvidenceRef | None` applies this fail-closed
precedence:

1. one valid explicit `[EVIDENCE:...]` marker belonging to the manifest revision;
2. one unique slide/page evidence item for a PDF page;
3. one unique normalized exact excerpt within the named manifest input;
4. one unique normalized fuzzy excerpt within that input at confidence `>= 0.9`;
5. otherwise `None`.

Unknown markers, file aliases, duplicate page/exact matches, fuzzy ties, and
cross-input evidence never produce a guessed citation.

## Provider boundary and Task 2.5 compatibility

Before any provider or provider-document mutation, indexing requires the
resolved view's `source_revision_id` to equal the requested revision, READY
course authority/scope, every required path and hash, and the configured provider
size limit.

Required inputs are verified as follows:

- PDF requires `ArtifactRole.PDF`, `application/pdf`, a checksum match, and PDF
  signature bytes.
- normalized Markdown requires `ArtifactRole.CLEANED`, `text/markdown`, a
  checksum match, and valid UTF-8 bytes.
- an image is considered only when `visual_semantic is True`, its declared media
  is PNG/JPEG, its path and hash exist, and declared dimensions are within
  `1..4096` on both axes. Pillow then verifies the actual decoded PNG/JPEG type,
  exact dimensions, bounds, and file integrity. Decompression-bomb warnings are
  converted to a safe `IndexingInputError`.

Only `normalized_markdown` receives the accepted initial whitespace chunking:

```text
max_tokens_per_chunk = 700
max_overlap_tokens = 100
```

PPTX, PDF, and image imports retain provider-default chunking (`None`). Each
input persists independently through the accepted one-to-many
`ProviderDocument` key. Upload, import operation, provider document, retry, and
cleanup identities resume per input without re-uploading completed work.

The original `pptx` document remains first and is returned as the Task 2.5 worker
compatibility anchor. A non-PPTX failure mirrors only its safe category onto that
anchor so the unchanged worker retry policy sees the correct classification;
successful completion clears it. The Task 2.5 claim, lease, recovery, and retry
contracts were not changed.
